# Promises (промисы)

> **Основа асинхронности JS.** Среда выполнения JavaScript однопоточная; асинхронность обеспечивает **Event Loop** — цикл событий с очередью задач (макрозадачи) и отдельной очередью микрозадач.

## Event Loop: однопоточность, стек и очереди

**JavaScript однопоточный** — в каждый момент выполняется только одна инструкция, есть один **стек вызовов** (call stack). Значит, тяжёлая синхронная операция «замораживает» всю страницу.

Но браузер (или Node.js) — не однопоточная среда. Долгие операции (таймеры, сеть, события, файлы) выполняют **Web API / хост-среда** в отдельных потоках, а когда они готовы — кладут колбэк в **очередь**. **Event Loop** следит за стеком: как только стек пуст, он берёт следующую задачу из очереди и выполняет её.

Упрощённо цикл выглядит так:

1. Выполнить весь **синхронный** код (пока стек не опустеет).
2. Дожать **все микрозадачи** (microtask queue) до конца — включая те, что добавились в процессе.
3. (При необходимости) отрисовать страницу (render / paint).
4. Взять **одну** макрозадачу (macrotask / task queue) и вернуться к шагу 2.

> Ключевое правило: **микрозадачи всегда выполняются раньше следующей макрозадачи**, и очередь микрозадач опустошается полностью перед рендером.

### Макрозадачи (macrotasks / tasks)
Отдельные «задачи» цикла. Между двумя макрозадачами браузер успевает отрисовать страницу.

- `setTimeout`, `setInterval`
- события (клик, ввод, загрузка)
- сетевые ответы (`fetch`, `XHR` — сам колбэк)
- `MessageChannel`, `setImmediate` (в Node.js)

### Микрозадачи (microtasks)
Отдельная, более приоритетная очередь: выполняется **сразу после текущего синхронного кода и перед следующей макрозадачей**.

- колбэки промисов: `.then`, `.catch`, `.finally`
- `queueMicrotask(...)`
- `MutationObserver`
- продолжение после `await` в `async`-функции

### Порядок выполнения — пример

```js
console.log('1 — sync');

setTimeout(() => console.log('2 — macrotask'), 0);

Promise.resolve().then(() => console.log('3 — microtask'));

queueMicrotask(() => console.log('4 — microtask'));

console.log('5 — sync');

// Вывод: 1, 5, 3, 4, 2
// Сначала весь sync-код (1, 5), затем все микрозадачи (3, 4),
// и только потом макрозадача таймера (2).
```

### Важные следствия
- **Промисы — это микрозадачи.** Поэтому `.then` сработает раньше, чем `setTimeout(..., 0)`.
- Микрозадачи могут «заморить» рендер: бесконечная цепочка `Promise.resolve().then(...)` не даст браузеру отрисовать страницу (в отличие от `setTimeout`, который пропускает рендер между задачами).
- `await` не блокирует поток: он приостанавливает **функцию**, а не весь Event Loop.

## Кратко о самих промисах
Объект, представляющий результат **асинхронной** операции: либо успех (`fulfilled`), либо ошибку (`rejected`). Позволяет избавиться от «callback hell».

## Три состояния
1. `pending` — ожидание.
2. `fulfilled` — выполнено (есть значение).
3. `rejected` — отклонено (есть причина/ошибка).

Состояние меняется **один раз** и уже не обратимо.

## Создание

```js
const promise = new Promise((resolve, reject) => {
  const ok = true;
  if (ok) resolve('готово');   // успех
  else reject(new Error('Ошибка'));
});
```

## Потребление: `.then` / `.catch` / `.finally`

```js
fetch('/api/users')
  .then(response => response.json())   // возвращаем новый промис → цепочка
  .then(users => console.log(users))
  .catch(error => console.error(error)) // ловит любую ошибку в цепочке
  .finally(() => console.log('завершено')); // выполнится всегда
```

## Цепочки
Каждый `.then` возвращает **новый** промис. Если вернуть значение — оно попадёт в следующий `.then`; если вернуть промис — цепочка дождётся его.

## Комбинаторы

| Метод | Что делает |
|-------|-----------|
| `Promise.all([...])` | ждёт **все**; падает при первой ошибке |
| `Promise.allSettled([...])` | ждёт все; возвращает статус каждого (без reject) |
| `Promise.race([...])` | результат **первого** завершившегося |
| `Promise.any([...])` | первый **успешный**, падает если все упали |

```js
const [user, posts] = await Promise.all([
  fetch('/api/user').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
]);
```

## Во Vue
Промисы — основа любых запросов к API в компонентах (получение данных при `onMounted`, обработка кнопок и т. д.).

Vue тоже опирается на очередь микрозадач: `nextTick()` откладывает колбэк до момента, когда DOM уже обновлён после изменения реактивных данных (внутренне это микрозадача на основе `Promise`).

```js
import { ref, nextTick } from 'vue';

const count = ref(0);

const increment = async () => {
  count.value++;
  // DOM ещё не обновлён
  await nextTick();
  // здесь DOM уже актуальный
};
```
